# Deployment and Operations

## Install paths

Two supported shapes (README.md): a bare-metal install on a RHEL-derivative
(Rocky 8, Python ≥3.8, SELinux disabled/permissive, Apache + `python38-mod_wsgi`),
or containers.

**Bare metal**: run `install_scripts/install_mpcc.sh` as root. Flags: `-d`
docker-build mode (skip `init_mpcc.sh`), `-m` MariaDB backend, `-p` PostgreSQL,
neither means SQLite under `db/`; `-x` checks out `main` instead of the latest
release tag (dev only). The installer creates/uses `env.db` for DB settings,
builds a venv, installs `requirements.txt`, and runs `install_scripts/init_mpcc.sh`,
which: generates `SECRET_KEY` into `.env`, writes `DJANGO_SUPERUSER_*` defaults,
auto-detects `ALLOWED_HOSTS` from the host's addresses, appends `env.db` and any
`.env.custom`, runs `collectstatic` and `migrate`/`createcachetable`, and
downloads the busybox 1.35 binary into `static/` (required by the
[initrd boot flow](/provisioning/pxe-boot-flow.md)). Optional env switches in
`env.example` control extra installs (`DISABLE_MPROV_SHARE`, `NO_ANSIBLE`,
`NO_MLX_OFED`, `NO_NVIDIA`, `DISABLE_SLURM`). `install_scripts/install.d/*.sh`
are ordered hook scripts and must stay idempotent (install_scripts/README.md).
After install, add your IP/FQDN to `ALLOWED_HOSTS` in `/var/www/mprov_control_center/.env`
or mPCC will refuse requests; the admin UI is `/admin/` with admin/admin — change it.

**Containers**: `Dockerfile`/`Containerfile` builds Rocky 8.8 + python38 +
httpd/mod_wsgi + MariaDB client libs, self-signs a localhost cert, creates the
venv, and runs `init_mpcc.sh -d` at start. `docker-compose.yml` pairs it with
`mariadb:10.4` via `stack.env`, waiting on the DB with `wait-for-it.sh`, and
persists two volumes: `media` (uploaded scripts,
`scripts/` stores artifacts on disk rather than in the DB) and `/etc/mprov/`.
`dev.docker-compose.yml` is identical but uses the `:dev` image. Bind mounts
for SQLite deployments: `db/` and `media/`.

## Configuration reference

Set env vars (containers) or `.env` (bare metal); `env.example` is the
annotated source of truth: `SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS`,
`SESSION_EXPIRE_SECONDS`, `TIME_ZONE`, `DB_*`, `DJANGO_SUPERUSER_*`, and the
`LDAP_*` block — mechanism described in
[architecture/auth](/architecture/overview.md#authentication). Never commit
`.env`; `.env.custom` is merged in by the installer for site overrides.

## CI and release

`.github/workflows/`: `dockerimages-dev.yml` builds/pushes
`ghcr.io/mprov-ng/mprov-control-center:dev` on every push to `main`;
`dockerimages-release.yml` publishes release-tagged images (SQLite/MariaDB/
PostgreSQL variants per README); `update_website.yml` syncs docs. The bare-metal
installer installs from git tags by default, so releases gate production.

## Backups and maintenance

- Database backups: `python3 manage.py dbbackup` (django-dbbackup) writes to
  `/var/www/mprov_control_center/backups/` (see `backups/README.md`).
- Cache table (`python manage.py createcachetable`) is required — the DB cache
  backs [job status toasts](/provisioning/job-queue.md#status-notifications-jobqueuesignalspy).
- Uploaded media under `media/` is authoritative for
  [scripts and files](/domain/data-models.md#scripts-app-scriptsmodelspy) — back it up with the DB.
- `gen_changelog.sh` builds changelog text from git tags.

## Operational gotchas

- Jobserver heartbeats expire after 60 s ([job queue](/provisioning/job-queue.md));
  clock skew or a stalled worker silently removes it from artifact-host
  selection.
- `DEBUG` must stay off in production; `SECRET_KEY` is regenerated by
  `init_mpcc.sh` re-runs (invalidating sessions).
- Enforcing SELinux breaks the Apache/mod_wsgi setup (README requirement).
- Images/repos are only reachable by nodes through mPCC redirects — if nodes
  404 on `/images/`, check `SystemImage.jobservers` is populated (it is cleared
  on every rebuild until a jobserver re-registers with `?addjs`).
